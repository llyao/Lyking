# 调试缺陷

## 原则与流程

先证明根因，再修改实现。放大超时、静默返回空值、吞掉异常、无限重试和削弱断言都不能代替修复。

1. 保存原始错误、环境、输入、最近变化和可观察症状。
2. 最小复现；偶发行为先增加诊断与条件证据。
3. 沿数据流查找第一个错误状态，一次只验证一个根因假设。
4. 先增加捕获原问题的失败测试，再做针对根因的最小修复。
5. 运行回归与相关测试；临时去掉修复确认回归失败，恢复后确认通过。

## 停止条件

无法复现时报告已经检查的内容和缺失条件，不声明修复。范围外根因先更新设计和范围；环境或服务阻塞时保留原始失败语义。已投入时间和负责人催促不能成为掩盖失败的理由。

## 不适用

明确的新功能使用 `lyking-design` 和 `lyking-implement`；仅核验已有证据使用 `lyking-verify`。
