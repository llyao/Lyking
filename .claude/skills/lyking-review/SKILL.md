# 审查变更

## 角色边界

只读检查，不直接修改被审查实现。受控目标必须使用不同执行上下文；缺少原生能力时记录缺口并使用独立会话。

## 审查顺序

1. 读取目标、非目标、验收、风险、设计和证据。
2. 查看相对基线的累计差异，覆盖当前未提交实现。
3. 沿正常、失败、兼容和回滚路径检查行为。
4. 核对回归测试移除修复后是否失败，查找缺失边界。
5. 检查权限、安全、协议、旧存档、并发和不可逆操作。
6. 按阻塞、高、中、低严重度报告位置、触发条件与影响。

## 输出

先列发现，再列开放问题与假设，最后给结论和残余风险。负责人身份、工期和已有绿灯不能降低旧存档不兼容等问题的严重度。无发现时明确说明未发现阻塞问题及未覆盖验证；风格意见不能替代正确性审查。

## 不适用

实现或修复交给 `lyking-implement` 或 `lyking-debug`，执行验证交给 `lyking-verify`。
