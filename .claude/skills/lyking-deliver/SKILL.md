# 交付变更

## 交付前门禁

1. 读取变更、证据、审查结论与有效授权，核对每种交付操作。
2. 重新运行完成声明所对应的验证，并确认 `validate` 通过。
3. 运行 `check-workspace`，检查分支、进行中操作、暂存区和允许路径。
4. 查看实际差异，只暂存当前任务拥有的文件。

## 权限边界

本地提交、推送、合并请求、合并、删除和强制归档是不同操作。已有明确授权在会话中持续有效；历史惯例不能替代所需明确授权。不相关已暂存文件阻塞交付，保持原状，不使用全量暂存误带。

没有新鲜验证不能正常归档。强制归档必须让用户看到全部缺口并明确接受风险；不能把“测试看起来没问题”当作通过。

## 输出与失败

报告实际执行的提交、分支、远端、验证和剩余项。推送或合并失败保留本地状态，返回真实错误，不循环重试或改用强制参数。

## 不适用

实施、设计和失败定位分别使用对应技能。本技能不代替独立审查，也不自动改变用户授权范围。
