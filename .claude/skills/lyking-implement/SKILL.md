# 实施变更

## 入口条件

直改目标必须明确；标准变更和受控目标必须处于 `ready` 或 `active`，具备对应工件。设计仍未确认时返回 `lyking-design`。

## 实施顺序

1. 读取根规则、领域上下文、变更记录、允许路径与当前计划。
2. 运行 `check-workspace`，确认分支、Git 操作状态和范围。
3. 阅读代码与现有测试，先增加最小失败测试，确认失败来自目标行为缺失。
4. 编写让测试通过的最小实现，再运行受影响测试。
5. 只在通过后整理必要重复或命名，随后重新验证。
6. 更新任务与证据，不能自行把实施结果视为已验证。

## 范围纪律

只修改 `paths` 或用户明确授权范围；时间压力不能代替回归验证。无关脏文件保持原状，不顺手重构相邻类。文件重叠、暂存区可能误带或新增兼容风险时先处理范围和设计。

## 不适用

未确认需求使用 `lyking-design`；未知根因使用 `lyking-debug`；交付操作使用 `lyking-deliver`。本技能不推送、合并、删除或归档；本地提交也遵循已有授权。
