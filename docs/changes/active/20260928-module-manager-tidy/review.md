# 模块管理器重新整理审查

## 设计阶段审查发现

### 中：F5 双入口的两种处置都有代价

保留 `ModuleComposer.Compose` 依靠注释约束，误用风险仍在，但删除它是公共接口变更，会扩大回归面并提前消耗后续阶段的演进空间。设计推荐选择 A（保留 + 明确警示），把 API 收缩留给 manifest/运行内核阶段一并考虑。此判断待用户确认。

### 中：口径统一的权威来源必须唯一

生命周期轨迹在上层 `design.md` 3.9 节、`IGameModule.cs` 注释、`ModuleHost.cs` 注释三处出现，措辞各异。统一时以 3.9 节决策记录为权威语义，但表述以"模块回调序列 + 宿主执行阶段 + 宿主状态"分层描述，避免把 `Ready`（宿主状态）误写成模块回调阶段。审查关注实施是否引入第四种口径。

### 低：文件移动的 git 历史可追溯性

`HostState` 拆分是新文件加删减；`ModuleCompositionException` 必须用 `git mv` 保持重命名追踪。审查时核对移动后 `git log --follow` 可达。

### 低：`ModuleHost.Health` 缓存顺序列表的行为等价性

缓存计划顺序引用列表后，`Snapshot` 的输出顺序必须与原实现完全一致（按计划拓扑序）。由 22 个既有测试中的健康相关用例覆盖，审查时核对测试断言顺序的用例仍然全绿。
