# 实施计划

## 目标

在现有客户端基础框架上交付可以组合、替换、无头测试的商业客户端能力。纯逻辑工程保持 `netstandard2.1` 与 C# 9；Unity、商店、账号和遥测供应商代码不进入本次范围。

## 阶段

1. **运行时线程与生命周期**：实现有界主线程派发器及关闭语义；修复模块启动取消时的独立有界回滚；确保下载后台完成仅通过派发器修改服务状态并派发事件。为 Unity 启动中的销毁增加取消和有界收敛策略。
2. **平台中立商业服务**：按能力域建立账号/游戏平台、隐私同意、支付验证委托、广告、通知/深链/归因、远程配置和遥测诊断合同；提供明确标记的模拟适配，统一取消、错误和隐私门控。
3. **存档与内容更新事务**：实现带格式版本的存档信封、迁移注册、保护器扩展、损坏检测和原子替换；实现带规范化签名载荷、信任密钥、期限、序号与恢复策略的内容清单验证，以及下载暂存、分块校验、原子激活和回滚。
4. **输入与集成演示**：实现设备无关动作映射和 UI 优先消费规则；通过同一客户端 Builder 装配模拟服务，在无头 Demo 演示隐私门控、购买验证边界、存档迁移与内容更新。
5. **验收与审查**：完成构建、测试、Demo、变更结构校验、差异空白检查和独立只读审查；记录每条命令真实结果。无 Unity 工程时明确保留编辑器验证缺口，状态保持 `active`。

## 依赖和边界

阶段 2、3、4 复用阶段 1 的派发和取消约定。存档及更新流程只依赖新合同与现有下载代理，不替换设置存储、资源加载或网络协议。支付和远程服务端校验保持客户端信任边界。模块按能力独立注册，不允许模拟实现被生产装配器静默选中。

## 完成条件

- 自动化测试覆盖派发器背压/关闭、启动取消回滚、后台下载事件派发、存档迁移/损坏/原子失败、更新签名/回放/损坏块/回滚、隐私同意门控和支付幂等委托。
- Solution 构建通过，所有测试通过，Demo 退出码为 0，工作流 `validate` 无 issues，`git diff --check` 通过。
- 独立审查无未解决阻塞；Unity 编辑器验证缺口已记录，不能据此声称真实平台适配已验证。
