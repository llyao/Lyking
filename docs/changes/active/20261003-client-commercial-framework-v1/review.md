# 独立审查

状态：独立初审与修复后复审均已完成；复审确认原 3 项 P2 已修复且无新增阻塞。自动结构校验不替代独立审查。

## 独立初审发现

- `[P2]` 固定协议为 ECDSA P-256，但信任根和轮换公钥原先仅检查 256 位密钥长度；其它 256 位曲线可能被当作 P-256 接受，造成协议互操作不一致。修复范围：`ContentUpdateContracts.cs` 与签名测试。
- `[P2]` 两个服务实例并发应用完全相同的有效清单时，后提交实例可能仅因序号已推进而失败，未满足精确重放幂等。修复范围：内容存储激活合同、文件存储和并发测试。
- `[P2]` 下载服务关闭时逐项取消令牌；同步取消回调可重入任务完成并修改正在枚举的取消源字典，令关闭异常中断。修复范围：下载关闭路径和同步取消回归测试。

## 修复后复审

- P-256 验签现在核对 256 位及曲线 OID `1.2.840.10045.3.1.7`；根密钥与轮换 SPKI 共用校验，secp256k1 被拒绝。
- 文件存储在激活锁内对活动序号、版本和规范化清单哈希完全相同的更新返回幂等 no-op；服务完成对应轮换事务并清理未激活暂存。测试覆盖共享和独立信任库竞争以及同序号冲突。
- 下载关闭的两条路径均快照取消源集合；同步内联取消测试覆盖有派发器和无派发器关闭。
- 独立审查未发现新的阻塞问题。审查者未运行测试，主线程重跑构建、测试和演示。

## 残余风险

- 内容指针文件自身损坏或截断时，当前恢复流程无法从指针中取得前一快照标识；现有恢复测试覆盖活动内容缺失，不覆盖指针损坏。原子替换降低中断概率，但没有独立恢复记录。
- 内置 ECDSA 信任库的轮换状态只在进程内存中。生产适配仍须跨重启持久恢复已提交轮换，并与内容指针激活保持事务一致；当前实现仅适用于测试和演示。
- 本次复审没有执行测试；以主任务独立重跑的最终验证证据为准。
- 下载回归用例已确认同步取消时任务清理发生在取消回调返回前，但 .NET 10 的旧实现没有稳定触发枚举异常；本机没有 Unity/Mono，目标运行时上的行为仍待验证。
