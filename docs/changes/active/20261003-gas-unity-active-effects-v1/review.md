# 设计自审

## 2026-10-03

- 范围检查：活动效果、属性账本、标签索引、时钟事务和事件契约均属于同一 Client 运行时扩展；周期效果、网络和表现层已明确排除。
- 兼容检查：保留现有 `GameplayEffectSpec` 和 `TryActivate` 的 v1 路径；新增 API 不要求调用方修改现有火球测试。
- 原子性检查：规格预检、贡献登记、标签登记和定时器安排被定义为一个事务，任何失败都要求完全回滚。
- 生命周期检查：有限效果由目标 ASC 时钟到期，无限效果必须显式移除；过期和移除幂等。
- 组合检查：活动贡献不会通过旧值快照回滚，基础值变化和多个效果可以组合。
- API 检查：效果应用使用带失败原因的结果对象；无限效果使用显式工厂，不复用非有限持续时间；`GetBase`、`Get` 和 `ApplyDelta` 的基础值语义已区分。
- 可观察性检查：新增活动效果和标签事件，区分目标 ASC 与来源能力，避免来源 ASC 重复转发。
- 未决项：具体新增类型的文件拆分、无限效果工厂命名、失败结果类型名称和 Unity 面板呈现方式留给实施计划确认，不影响当前架构决策。

## 独立只读复审

### 2026-10-03

- 复审发现：极值叠加在移除时可能溢出并留下半清理状态；已改为先预检所有移除后的有效值，失败时保持活动句柄、贡献和标签不变，并增加回归测试。
- 复审发现：`ActiveEffectApplied` 回调同步移除会造成陈旧属性/标签事件；已增加活动效果事件序列的不可重入保护，移除请求返回 `false`，原事件序列保持一致。
- 复审发现：无限 `DamageEffect` 可绕过 v1 火球拒绝边界；已显式检查 `IsInfinite`，并增加资源、目标和冷却不变的回归测试。
- 复审发现：零增量效果会发布伪属性变化；已只为有效值确实变化的属性生成通知。
- 复审发现：调度器抛出的参数异常可能被误分类；已将调度调用单独归类为 `SchedulingFailed` 并统一回滚。
- 复审发现：纯标签效果被错误拒绝；已允许无属性修饰器但至少授予一个标签的有限或无限效果，并增加生命周期测试。
- 复审发现：句柄 ID 在不同 ASC 内从 1 开始可能误移除同编号效果；已为运行时句柄加入 ASC 归属令牌，跨 ASC 句柄查找失败。
- 复审发现：活动标签枚举顺序不稳定；已按标签名序号排序后再登记和发布标签事件。

### 结论

独立复审未发现仍需阻塞实现的高风险问题。自定义时钟若在 `Schedule` 已登记回调后再抛异常，接口本身没有提供可取消的定时器 ID，仍需遵守“抛异常不产生可见副作用”的时钟契约；当前内置 `ManualGameplayClock` 满足该契约。固定 Unity 2022.3.40f1、真实 `Space` 输入和运行截图尚未验证，因此变更保持 `active`。
