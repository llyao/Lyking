# 验证边界

验证对应当前代码、环境和验收声明。证据包含日期、实际命令、退出码、测试通过与失败数量及关键输出；旧日志不能代替修改后的验证。

| 范围 | 验证入口与证据 |
|---|---|
| 工作流工具 | `dotnet test Tool/AiWorkflow/Tests/Lyking.AiWorkflow.Tests.csproj`；路径、状态、命令、适配及临时 Git 仓库测试 |
| Unity 纯逻辑 | 编辑模式测试；新增 Unity 工程后在领域上下文记录真实命令 |
| 场景、生命周期、运行时集成 | 运行模式测试，必要时记录运行条件和复现步骤 |
| 服务端 | 对应 .NET 测试、集成和部署配置检查 |
| 共享契约 | 客户端与服务端共同编译、协议和存档兼容验证 |
| 美术、界面与交互 | 当前版本真实运行截图或明确人工验收记录 |

当前游戏目录尚无可执行工程，不虚构 Unity 或业务 .NET 测试命令。只运行相关测试；受控目标增加必要集成验证和不同上下文的只读独立审查。

结构检查只能验证工件、状态、编码、链接和适配一致性，不能验证测试日志真实性、证据与代码的新鲜对应或真人审查身份。声明 `verified` 前由操作者核对这些事项，记录必需平台检查缺口并保持 `active`。失败时保留原始失败语义，修复后重新取证。
