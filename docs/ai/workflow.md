# 工作流

需求先读取[上下文地图](../../CONTEXT-MAP.md)，结合显式路径运行 `route`。自由文本只形成候选，由设计阶段核对实际依赖与需求。不能确定所有权时停留在根上下文。

## 任务档位

| 档位 | 使用条件 | 必需工件 |
|---|---|---|
| 直改 | 无可见行为、公共接口、协议、持久化、安全和架构选择变化，单会话可完成 | 不建变更目录 |
| 标准变更 | 普通功能、缺陷和局部重构 | `change.md`、`evidence.md` |
| 受控目标 | 共享契约、存档、协议、安全、不可逆数据、至少三个领域、多人并行、跨会话、超过八条验收或迁移兼容回滚 | 标准工件及 `design.md`、`plan.md`、`tasks.md`、`review.md` |

用户可以升级档位。普通规模信号只有说明理由后才允许降级；协议、存档、安全、不可逆风险必须消除或继续使用受控目标。风险标准变更也需要独立审查。

## 状态与闭环

固定边为 `draft → ready → active → verified → archived`，另允许 `active → blocked → active`。关键决策未确认时保持草稿；失败时保持执行中，需要外部输入时阻塞。不得跳过状态边。

路由后明确验收与范围、实施最小改动、运行相关验证、按风险独立审查，最后依当前授权交付。变更元数据位于 `change.md` 的唯一 `lyking-ai` 注释块；`paths` 声明仓库相对路径，`areas` 与 `riskSignals` 描述语义范围和风险。归档目录只能保存 `archived` 记录；归档后冻结，后续问题使用新记录。

## 工具入口

从仓库根运行 `dotnet run --project Tool/AiWorkflow/Lyking.AiWorkflow.csproj -- help` 查看四个命令。所有命令标准输出为单个 JSON 文档，退出码分别为成功 `0`、参数 `2`、输入 `3`、验证 `4`、工作区阻塞 `5`、内部错误 `10`。

`validate` 检查结构、路径、链接、工件和门禁；它不能证明 Markdown 文字中的测试真的运行过。操作者必须按[验证边界](verification.md)建立当前版本证据。`sync-adapters --check` 只读比较；`sync-adapters` 按清单重建受管适配，不覆盖非受管同名文件。`check-workspace` 只读报告 Git 分支、操作和范围。

## 失败与交付

必需验证失败或独立审查未通过时不得进入已验证。修改已验证内容时回到实施流程重新取证；归档后的后续问题创建新变更。无关脏文件保持原状，范围外已暂存文件阻塞交付。

本地提交服从已有授权；推送、合并、删除和强制归档需要明确授权。第一版不自动执行这些操作，也不包含看板、租约、心跳、控制器、工作树池或外部平台集成。
